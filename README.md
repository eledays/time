# Дневник поездок

Минималистичный личный дневник перемещений на Flask и SQLite. Приложение сохраняет реальные поездки, подсказывает уже известные места и оценивает время составного маршрута по вашим собственным данным.

## Возможности

- вход через Яндекс ID (OAuth 2.0);
- сохранение начальной точки и времени до закрытия приложения;
- автоматический часовой пояс с ручной настройкой в профиле;
- выбор точного времени отправления и прибытия через компактный диалог;
- завершение поездки после прибытия или очистка ошибочного старта;
- автодополнение мест и создание нового места прямо из поля;
- девять видов перемещения;
- номер автобуса, ветка метро, стоимость и тариф такси;
- расчёт маршрута из последовательности до 20 точек;
- среднее, минимальное и максимальное время по накопленным поездкам;
- отдельные разделы поездок, мест, карты и профиля со статистикой;
- координаты, описания и цвета меток сохранённых мест;
- интерактивная карта мест и связей между ними;
- удаление отдельных поездок, всей истории или аккаунта со всеми данными;
- мобильный интерфейс в лаконичной тёмной теме;
- изоляция поездок каждого пользователя и CSRF-защита.

## Локальный запуск

Нужен Python 3.12 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
flask --app run.py db upgrade
flask --app run.py run --debug
```

Откройте `http://127.0.0.1:5000`.

База создаётся командой миграции в `instance/time.sqlite3`. Путь можно заменить через `DATABASE_URL`.

## Настройка Яндекс OAuth

1. Создайте приложение на странице OAuth Яндекса.
2. Добавьте только право `login:info`.
3. Укажите callback URL `http://127.0.0.1:5000/auth/callback`.
4. Перенесите ID и секрет приложения в `.env`:

```dotenv
SECRET_KEY=длинная-случайная-строка
YANDEX_CLIENT_ID=идентификатор-приложения
YANDEX_CLIENT_SECRET=секрет-приложения
DATABASE_URL=sqlite:///time.sqlite3
```

OAuth-приложению требуется только разрешение `login:info`. Email, телефон и портрет
пользователя Сервис не запрашивает и не хранит.

## Карта

Карта работает без отдельного API-ключа. Для интерфейса используется OpenLayers, а
спутниковую подложку предоставляет Esri World Imagery. OpenStreetMap не используется.

Полная инструкция по production-развёртыванию через nginx, Gunicorn и systemd,
включая миграции, health checks, резервные копии, восстановление, обновление и
откат, находится в [`docs/production.md`](docs/production.md).

Production-режим не запустится без HTTPS-адреса, доверенного proxy и Host,
настроенного OAuth, абсолютных путей SQLite и стойкого `SECRET_KEY`.

Перед публикацией заполните реквизиты Пользовательского соглашения и Политики
обработки персональных данных:

```dotenv
LEGAL_OPERATOR_NAME=ФИО, ИП или наименование организации
LEGAL_OPERATOR_EMAIL=privacy@example.ru
LEGAL_OPERATOR_ADDRESS=почтовый адрес оператора
LEGAL_OPERATOR_ID=ИНН / ОГРН / ОГРНИП при наличии
LEGAL_DATA_STORAGE_LOCATION=город и страна размещения основной базы
LEGAL_HOSTING_PROVIDER_NAME=наименование провайдера
LEGAL_HOSTING_PROVIDER_LOCATION=город и страна провайдера
LEGAL_DOCUMENT_VERSION=1.1
LEGAL_EFFECTIVE_DATE=2026-09-14
LEGAL_BACKUP_RETENTION_DAYS=30
LEGAL_LOG_RETENTION_DAYS=30
```

Необязательные `LEGAL_RKN_NOTICE_DATE`, `LEGAL_CROSS_BORDER_TRANSFER`,
`LEGAL_CROSS_BORDER_NOTICE_DATE` и `LEGAL_CROSS_BORDER_COUNTRIES` заполняются,
только если они применимы по результатам юридической оценки фактического
развёртывания. Их отсутствие не блокирует production-запуск.

Production-режим проверяет обязательные реквизиты при запуске. Документы отражают
текущую механику приложения, но перед реальным запуском их нужно сверить с юристом,
фактическим хостингом, подрядчиками и сроками хранения. Отдельно проверьте, нужны
ли уведомления Роскомнадзору и требования к трансграничной передаче и локализации.
При любом существенном изменении документов увеличьте
`LEGAL_DOCUMENT_VERSION`: пользователи увидят новую редакцию и явно примут её.

## Структура

```text
app/
├── auth/          # OAuth и пользовательская сессия
├── main/          # страницы и JSON API
├── static/        # стили и интерактивность
├── templates/     # Jinja-шаблоны
├── models.py      # SQLAlchemy-модели
├── services.py    # бизнес-логика расчёта
└── __init__.py    # фабрика приложения
tests/             # интеграционные тесты
deploy/            # systemd, nginx и резервное копирование
docs/              # production runbook
migrations/        # версионируемая схема базы данных
run.py             # точка входа
```

Архитектура намеренно небольшая: два blueprint-модуля отделяют авторизацию от продукта, а расчёт вынесен из HTTP-слоя, но лишних репозиториев и абстракций для компактного SQLite-приложения нет.
